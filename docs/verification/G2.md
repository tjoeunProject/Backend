# G2 사용자 권한·응답 검증

RP-02·03·04를 같은 변경으로 처리한다. G1 빌드 기반 PR 위의 변경이며 기능 diff에 빌드 설정을 중복시키지 않는다.

- 실제 MockMvc 요청에서 다른 사용자의 일정 삭제가 200을 반환하는 assertion 실패를 확인한 뒤 403으로 변경했다.
- 일정 생성·수정, 좋아요 조회, 프로필 응답 검사 4개도 수정 전 실제 assertion 실패 후 통과했다.
- 최종 Java 검사 10개 통과: 소유권/응답 7개, 정상 생성 반복 측정 1개, 기본 컨텍스트/저장소 2개. 실패·오류·skip 없음.
- 권한을 거절하면 일정·좋아요가 바뀌지 않고 장소 공급자가 호출되지 않는 것을 확인했다. 정상 본인 생성·삭제 및 좋아요 응답도 검사했다.
- 로그인 사용자를 서버 인증 컨텍스트에서 조회하며, 생성 요청의 타인 memberId를 거절한다. 공개 일정 조회 계약은 유지한다.
- 프로필, 좋아요, 내 일정 목록은 DTO로 반환한다. 클라이언트는 routeId/routeName/likeId 등 DTO 필드를 사용해야 한다.

## 성능

동일한 본인 일정 생성(빈 일차) 요청을 H2/MockMvc에서 비교했다. 워밍업 3배치 후 7배치, 배치당 20회, 동시성 1, 외부 호출 0. 요청당 중앙값 2.9243ms → 4.2624ms. 사전 예산은 기준의 1.5배 + 5ms이며 충족했다. 추가 인증 조회에 비용이 들며 속도 개선 주장은 하지 않는다. baseline→candidate 순서이고 별도 JVM/캐시 영향이 있어 통계적 유의성을 주장하지 않는다.

원시값은 G2-performance.json, 재현은 `gradlew.bat --no-daemon test`. 실제 Oracle·브라우저·유료 공급자 통합은 미실행이다. 요구사항 리뷰에서 소유권과 응답 경계를, 유지보수성 리뷰에서 공통 CurrentUser와 DTO 변환을 각각 확인했다. 자동 병합하지 않는다.
