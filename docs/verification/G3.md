# G3 backend: token lifecycle

Access and refresh credentials have explicit signed token_use claims and unique jti values. Both are persisted. Refresh validates the stored active row under a pessimistic write lock, rotates the pair, and rejects replay. Logout and soft deletion revoke both kinds. Active-token query requires both flags to be false. Invalid authentication returns 401; authorization denials remain 403.

TDD: the unchanged access-as-refresh API assertion failed with expected 401 / actual 200 on G2, then passed on G3. Initial duplicate-token setup interference was resolved before retaining the actual assertion failure. Final full Java suite: 17 tests, zero failures/errors/skips (6 lifecycle, 1 registration benchmark, 10 existing). Real MockMvc, JWT parsing and H2 persistence; external PlaceService mocked only in ownership tests. Concurrent Oracle locking, expired-clock fixtures and real browser behavior remain unverified.

Performance: identical registration benchmark, 3 warmup requests, seven batches of three, concurrency 1, no provider calls. Predeclared budget baseline * 1.5 + 10ms. See G3-performance.json. No production speedup claim.

## Deployment prerequisites / rollback

JWT values now require TOKEN.TOKEN capacity of at least 1024 characters. Before deploying, inspect actual Oracle column naming/length and apply a reviewed migration such as `ALTER TABLE TOKEN MODIFY (TOKEN VARCHAR2(1024 CHAR));` with the real schema owner. No production SQL has been run. Existing untyped tokens will be rejected: require re-login. Old app versions must not be deployed while relying on new token_use semantics. Frontend must refresh on 401 and must not refresh ownership 403; the linked frontend PR supplies that change. HASHIDS_SALT and length must match frontend configuration (encoding is not authorization).

Requirements review: actual security filter, refresh controller, logout handler and deletion entrypoint traced. Maintainability review: shared revocation service, no credential logging, existing error handler reused. No automatic merging. Database migration and real-service checks remain release blockers; draft PR is reviewable code, not production-complete certification.
